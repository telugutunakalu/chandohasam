# Telugu MDLM — pretraining

A masked-diffusion language model (MDLM) for Telugu. Stage 1 pretrains on general
Telugu (Wikipedia + AI4Bharat corpora) for fluency; stage 2 specialises the
checkpoint to metrical poetry. Canvas: 512 tokens. Logging is local only.

## Setup

```bash
cd diffusion_pretraining
uv sync                      # Python 3.12, torch 2.14 (CUDA 13), deps pinned in uv.lock
uv run pytest -q             # tokenizer tests
```

## Layout

| Path | What it is |
|---|---|
| `tokenizer/` | The syllable-aware tokenizer (copied from `~/phd_workspace/syllabe_aware_tokenizer`): one token per akshara, byte-BPE failover, zero OOV. Frozen vocabulary: `telugu_alldomain.tokenizer.json` (45,591 tokens; `<pad>`=0, `<unk>`=1, `<bos>`=2, `<eos>`=3, `<mask>`=4). |
| `tokenizer/aksharanusarika_split.py` | Akshara segmentation comes from `meter_engine/aksharanusarika.py`, so tokens and the meter engine always agree on akshara boundaries (ఁ stays on its akshara, ZWNJ is stripped). |
| `data_prep/download.py` | Downloads the corpora into `../pretraining_datasets/raw/` and writes `manifest.json` (Hub commit, licence, size and sha256 of every file). |
| `data_prep/build_corpus.py` | Raw → clean, deduplicated, poem-free token files in `../pretraining_datasets/tokens/<source>/{train,val,test}.bin`, with `meta.json` and `report.md` (funnel, token counts, 20 decoded training canvases). |
| `mdlm/` | The model (`model.py`: bidirectional transformer, RoPE, RMSNorm, SwiGLU, tied embeddings, no time input), the MDLM objective (`diffusion.py`), samplers (`sampling.py`: ancestral with caching, confidence), data mixture (`data.py`), sample metrics (`metrics.py`), training (`train.py`) and a throughput benchmark (`benchmark.py`). |
| `tests/` | Tokenizer (lossless, zero OOV, aksharanusarika alignment), data prep, and MDLM (loss ≈ ln V at init, masked positions only, samplers, overfitting, deterministic batches). |

## Training

The current run is the 120M pilot; every hyperparameter and weight tensor is
documented in [docs/pilot120m_model_card.md](docs/pilot120m_model_card.md)
(generated by `mdlm.describe`; each run also writes `runs/<run>/MODEL_CARD.md`).

```bash
uv run python -m mdlm.train --run pilot120m --preset small-768 --total-steps 76000 \
    --weights '{"sangraha": 0.75, "indiccorp": 0.20, "wikipedia": 0.05}'     # re-run to resume
uv run tensorboard --logdir runs                                               # local only
uv run python -m mdlm.benchmark --presets small-512 small-768 --micro-batch 8 16
uv run python -m mdlm.judge --samples runs/pilot120m/samples/step_0005000.txt  # gen-PPL (Gemma-3-1B)
```

The pilot runs under a systemd user service, [deploy/telugu-mdlm-pilot.service](deploy/telugu-mdlm-pilot.service):
it restarts the trainer 60 s after any crash, starts it at boot, and keeps the laptop from
suspending. Out-of-memory errors retry the step with a smaller micro-batch; evaluation and
sampling failures are skipped.

A second service, [deploy/telugu-mdlm-judge.service](deploy/telugu-mdlm-judge.service), scores each
new sample file with the Gemma-3-1B judge on the CPU (low priority, GPU untouched; the
~4 GB judge lives in a child process that exits after each round, and the kernel's OOM killer
takes it before the trainer) and appends
the generative perplexity to `runs/pilot120m/judge.jsonl`. Reference values on this corpus:
real Telugu 16.9, word-shuffled Telugu 64.9.

```bash
systemctl --user status telugu-mdlm-pilot      # state; the log is runs/pilot120m/train.log
systemctl --user stop telugu-mdlm-pilot        # pause (saves a checkpoint), e.g. to use the GPU
systemctl --user start telugu-mdlm-pilot       # resume
```

Growth ladder (`mdlm.model.PRESETS`): `small-768` (120M) → `grow-1536x16` (523M)
→ `grow-1536x32` (976M), or `grow-2304x16` (1.12B) directly. Every stage keeps
head_dim 64, the RoPE base, the tokenizer and mlp_hidden = 8/3 · d_model, and
widths are whole multiples of the previous stage, so each stage can be
initialised function-preservingly from the one before:

```bash
uv run python -m mdlm.grow --from runs/pilot120m --to grow-1536x16 --out runs/pilot120m/grown/grow-1536x16.pt
uv run python -m mdlm.train --run stage1-523m --preset grow-1536x16 \
    --init-from runs/pilot120m/grown/grow-1536x16.pt --warmup-steps 1000 ...
```

`mdlm.grow` widens by cloning (HyperCloning: every hidden vector carried k times,
each head repeated, linear layers as k × k grids of w/k plus noise that cancels
across the copies, final RMSNorm gain / k for the tied output) and deepens by
inserting copies of existing blocks whose output projections are zero. The grown
model computes exactly the same logits as the one it came from
(`tests/test_grow.py`, float64), and `--check` compares the two on real weights
before writing. `--init-from` starts the new run with a fresh optimizer at step 0.

Each run writes `runs/<run>/`: `config.json`, `metrics.jsonl`, TensorBoard logs,
`samples/step_*.txt`, `snapshots/ema_step_*.pt` (bf16 EMA weights every 5,000
steps) and two checkpoint slots `ckpt_a.pt` / `ckpt_b.pt` (model, EMA, optimizer,
step), written alternately and fsync'ed so a power cut always leaves one complete
checkpoint. Re-running the same command resumes from the newest readable slot;
batches, masks and times are a pure function of (seed, step). Checkpoints are
saved every 15 min, on Ctrl-C/SIGTERM, immediately when a laptop loses mains
power (then every 5 min on battery), and before exiting at 15 % battery. The loss is computed only at masked
positions, in chunks whose logits are recomputed during backward, so the
45.7k-wide output layer fits in 8 GB.

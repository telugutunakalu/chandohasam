# Model card — `pilot120m` (small-768)

Generated by `mdlm.describe` from the code and configuration that the run uses.

## Summary

- Masked diffusion language model (MDLM, Sahoo et al. 2024) for Telugu, trained from scratch.
- **120,048,384 parameters**: 84,953,856 in the transformer, 35,094,528 in the tied embedding (45,696 × 768).
- 12 blocks × d_model 768, 12 heads × 64, SwiGLU 2048, canvas 512 tokens.
- Training: 76,000 steps × 65,536 tokens = **4.98B tokens** (41 tokens per parameter).
- Measured speed on the RTX 5050 Laptop: 20,939 tokens/s, so about 66 h (2.8 days) of pure training.

## Fixed design choices (not configurable)

| choice | setting |
|---|---|
| block layout | pre-norm: x + Attn(RMSNorm(x)), then x + SwiGLU(RMSNorm(x)); final RMSNorm before the output layer |
| attention | bidirectional (no causal mask), `F.scaled_dot_product_attention`, softmax scale 1/√head_dim |
| positions | rotary embeddings (RoPE) on queries and keys, interleaved channel pairs, no learned position embedding |
| MLP | SwiGLU: down(SiLU(gate(x)) ⊙ up(x)) |
| biases | none (every linear layer is bias-free) |
| dropout | none |
| time conditioning | none: the absorbing-state denoiser's optimum is independent of t (Ou et al. 2024; Zheng et al. 2024) |
| embeddings | input and output tied (one matrix) |
| precision | fp32 master weights and optimizer state; bf16 autocast for the forward/backward; fp32 cross-entropy |

## Diffusion objective

| item | setting |
|---|---|
| forward process | absorbing state: each token becomes `<mask>` independently with probability t (log-linear schedule, α_t = 1 − t) |
| time sampling | t ~ U(ε, 1) with ε = 0.001, low-discrepancy: one offset u, t_i = ε + (1 − ε)·((u + i/B) mod 1) across the batch |
| parameterisation | SUBS: `<mask>`, `<pad>`, `<unk>` and padding logits are −∞; unmasked tokens are copied (no loss) |
| loss | NELBO per token = Σ over masked positions of CE / t, divided by batch × length (nats/token; exp gives a perplexity bound) |
| memory | output layer evaluated only at masked positions, in chunks of 2,048 whose logits are recomputed in the backward pass |

## Tokenizer

- `diffusion_pretraining/tokenizer/telugu_alldomain.tokenizer.json` (sha256 `200c814d84cc1b88bccdea3e4131a4c2fee296d050587e5d3da99f22d73d30fc`), 45,591 tokens.

- One token per akshara, split by `meter_engine/aksharanusarika.py` (ఁ stays on its akshara, ZWNJ is stripped); rare aksharas fall back to byte-level BPE, so nothing is ever out of vocabulary.

## Evaluation and sampling

- Every 1,000 steps, with the EMA weights: validation NELBO and perplexity bound per source on 128 fixed canvases each (fixed times and masks); cross-entropy by mask-rate bin; masked-token accuracy at 15 / 50 / 85 % masking.
- Every 5,000 steps: 16 samples of 512 tokens with the ancestral sampler (256 steps, float64 Gumbel draws); logged: token entropy, distinct-1/2/3, repeated 4-grams, rare-akshara share, dangling viramas, Telugu share, share of words attested in validation text.
- Offline: generative perplexity with `mdlm.judge` (google/gemma-3-1b-pt, float32; real Telugu 16.9, word-shuffled 64.9 on 30 validation canvases).

## Checkpoints and recovery

- Two alternating fsync'ed slots `ckpt_a.pt` / `ckpt_b.pt` (model, EMA, optimizer, step); saved every 15 min, on Ctrl-C/SIGTERM, at once when mains power is lost, every 5 min on battery, and before exiting at 15 % battery. Re-running the command resumes from the newest readable slot.
- Permanent bf16 EMA snapshots every 5,000 steps in `snapshots/`.
- CUDA out-of-memory during a step: partial gradients are cleared and the step is retried with half the micro-batch (same computation, smaller pieces). During evaluation, sampling or a snapshot: that item is skipped. A non-finite loss or gradient skips the update; 100 in a row stops the run with exit code 3.
- Supervisor: `deploy/telugu-mdlm-pilot.service` (systemd user service) restarts the trainer 60 s after any crash, starts it at boot, and holds sleep/idle/lid-switch inhibitors so the laptop does not suspend. Exit codes: 0 finished or stopped, 75 low battery (restart; waits for mains), 3 diverged (no restart).

## Growth compatibility

The model is shaped so it can later be grown into larger models, each initialised from the previous one function-preservingly (the grown model starts with exactly the same outputs):

- head_dim fixed at 64 and the same RoPE base: grow by adding heads, never by widening them.
- mlp_hidden = 8/3 × d_model, and each stage's d_model a whole multiple of the previous one: width grows by cloning units and heads with rescaled weights (HyperCloning-style).
- Depth grows by inserting blocks whose residual output projections start at zero (identity blocks).
- Same tokenizer, vocabulary, padding and tied embeddings at every stage.

# Runs — constrained decoding of Telugu padyams

Every run of [`meter_engine/metrical_decoder`](../../meter_engine/metrical_decoder/)
from 2026-09-24 to 2026-09-26. The decoder generates a padyam in any of the 37
catalogued meters. It uses the three IndicNeuroSym decoding strategies on top of
the metrical DAWG (gaṇa) and the prāsa and yati engines.

The design, and every finding that changed it, is in
[`meter_engine/CONSTRAINED_DECODING_PLAN.md`](../../meter_engine/CONSTRAINED_DECODING_PLAN.md):
- §12: findings from the random-logit controls;
- §14: Gemma-4 E4B;
- §15: DiffusionGemma;
- §16: the three models compared.

This file describes each run folder: what it holds, how it was produced, and
what it shows. Every count below was recomputed from the run's own
`results.jsonl`.

## The program shared by every run

**Task.** Write a padyam in a given meter on a given topic, for each of the 37
catalogued meters.
- **Prompt.** The meter's rules, generated from the catalogue
  (`python -m metrical_decoder rules METER` prints them), plus the topic, in
  the model's chat template.
- **Grid.** Three topics × five seeds (42, 49, 56, 63, 70) per meter, one unit
  per poem:
  - **T1** తల్లి ప్రేమ అన్నింటికంటే గొప్పది
  - **T2** హనుమంతుడు సముద్రమును దాటి లంకను చేరెను
  - **T3** శ్రీరాముడు సీతాదేవిని రక్షించుటకు లంకకు వెళ్ళెను
- **Size.** A full grid is 37 × 3 × 5 = **555 poems per mode**. The trials use
  T1 and seed 42 only (37 poems per mode).

**Modes** (`metrical_decoder/strategies.py`):

| mode | what it does |
|---|---|
| `baseline` | free generation: sample the whole vocabulary until end of text; the enforcer only watches and records where the text leaves the meter |
| `masking_only` | IndicNeuroSym Alg. 5 without backtracking: sample from the tokens the enforcer allows |
| `masking_backtrack` | Alg. 5: the same mask; a checkpoint every 3 tokens (ring of 15); backtrack when fewer than 3 tokens are allowed, when the allowed mass falls below 0.001, or on a stall; temperature +0.15 per consecutive backtrack (cap 1.2, decaying over 6 tokens); at most 30 backtracks |
| `hybrid` | Alg. 6: the same mask, then an accept-state re-ranking of the top 100 allowed candidates that prefers line-completing tokens; backtracking only as a last resort |

**Enforcement** (constrained modes, `--enforce gana,prasa,yati --profile strict`).
- **Gaṇa** comes from the metrical DAWG (`indic_meter_dawg`).
- **Prāsa and yati** are enforced jointly with gaṇa by registers that consult
  the prāsa and yati engines' own rules.
- **Liveness is exact.** The mask only allows tokens after which the poem can
  still be completed, so no strategy can reach a dead end. Every dead end in
  these runs was an enforcer bug, found and fixed.
- **Line breaks** are forced only when a line cannot continue
  (`force_nl=must_end`).

**Decoding settings** (`run.json` → `config`).

| | autoregressive (E4B, 26B) | DiffusionGemma |
|---|---|---|
| sampling | temperature 0.7, top-p 0.9 | the model's schedule, 0.8 → 0.4 over 48 passes per 256-position block; entropy bound 0.1 |
| token budget (constrained) | per meter, the most tokens any poem can take: (longest akshara + 1) × aksharas + lines (`token_budget` in `run.json`; ఉత్పలమాల 1,044) | same |
| token budget (baseline) | 3 × the meter's longest poem + 32 | end of text allowed |

Masks are computed in 4 worker processes (`--mask-workers 4`).

**Models.**
- **Gemma-4 E4B** (`google/gemma-4-E4B-it`) and **Gemma-4 26B-A4B**
  (`google/gemma-4-26B-A4B-it`): BF16 through Hugging Face, plain chat
  template, no prefill. For E4B, an empty thinking-channel prefill makes it
  analyse the rules in English (plan §12).
- **DiffusionGemma 26B-A4B**: NVIDIA's NVFP4 checkpoint
  (`nvidia/diffusiongemma-26B-A4B-it-NVFP4`), loaded by the project's own
  loader with the experts decoded once to BF16 (`--resident`, about 52 GB).
  - It needs an empty thinking-channel prefill; without it, all its mass goes
    to the channel token.
  - It is constrained through a frozen-prefix canvas: committed tokens stay
    fixed while the model keeps drafting the rest (plan §15).

**Evaluation** (`metrical_decoder/evaluate.py`). The enforcer never judges its
own output; the independent engines do:
- `gana_strict`: the canonical scansion, with the rules the enforcer generates
  under, accepted by the meter's prosodic automaton;
- `gana`, `prasa_strict`, `yati_strict`: `chandohasam.analyze` with the meter
  forced, under the strict profile and yati sandhi `off`;
- `prasa_relaxed`, `yati_relaxed`: the same under the relaxed profile and yati
  sandhi `hypothesis`;
- `all_strict` = `gana` ∧ `prasa_strict` ∧ `yati_strict`; `all_relaxed`
  likewise.

This README's "in meter" is `gana_strict` ∧ `prasa_strict` ∧ `yati_strict`.
It differs from `all_strict` in one poem only, noted under
[`2026-09-26_diffusion_baseline`](#2026-09-26_diffusion_baseline).

**Trace.** For every generated token (and every backtrack) `traces.jsonl`
records:
- the token's log-probability under the model over the whole vocabulary at
  temperature 1 (`logp`), and its rank there;
- the probability it was actually drawn with (`p_pick`);
- the number of allowed tokens and the model's mass on them (`n_valid`,
  `valid_mass`);
- the entropy, and the model's top 5 with each candidate's validity.

Together these show how far the model's own choice was from the meter at every
step.

**Machine.** The GB10 shares one memory between GPU and CPU:
- `mem_watchdog.sh` stops a run if available memory falls below 6 GB;
- `mem_trace.sh` logs memory, synced to disk so the log survives a crash;
- one model runs on the GPU at a time.

## Files in a run folder

| file | what it holds |
|---|---|
| `run.json` | the configuration: model, meters, modes, topics, seeds, decoding config, enforcement, mask workers, per-meter token budget, start time |
| `prompts.jsonl` | one row per (meter, topic): the chat messages, their hash (`prompt_sha`) and token ids |
| `results.jsonl` | one row per poem, keyed `meter\|topic\|mode\|seed`: the text, `status` (`complete`, `eos`, `budget`, `dead_end`), statistics (`n_tokens`, `seconds`, `n_backtracks`, …) and `eval` (the verdicts above) |
| `traces.jsonl` | one row per poem: the same key and the per-token trace |
| `traces.part1.jsonl`, `traces.part2.jsonl`, `TRACES_SPLIT.txt` | the three traces over GitHub's 50 MiB limit, split at a line boundary; `traces.jsonl` is gitignored there. Rebuild it with `cat traces.part1.jsonl traces.part2.jsonl > traces.jsonl` (sha256 in `TRACES_SPLIT.txt`) |
| `summary.md` | a table per meter × mode (`python -m metrical_decoder summarize RUN_DIR`), described below |
| `report.md`, `report.json` | token-level analysis (`python -m metrical_decoder report RUN_DIR …`), by strategy, by position in the line (prāsa / yati / line start / other) and by meter |
| `run.log` | the progress log: one line per poem with status, tokens, verdicts and seconds |
| `superseded_*_{results,traces}.jsonl` | rows replaced by a rerun, kept for comparison (see the run's history) |
| `rule_audit.json` | which poems a rule change could have altered, and why (`audit_rule_change.py`) |
| `run_*.json` | `run.json` as it was before a rerun |
| `SEEDED_FROM.txt`, `SUPERSEDED_VOWEL.txt` | notes on rows copied from a trial, or replaced after a rule change |
| `pid`, `watchdog.log`, `mem_trace*.log` | process id of the run, the memory watchdog's log, and the memory trace |
| `g1/` … `g5/`, `*.log` (controls) | a control split into parallel groups of meters, each a run folder of its own, with its log beside it |

**`summary.md` columns:**
- `n`: the number of poems.
- `gana_strict` … `all_relaxed`: the **percentage** of poems passing each
  verdict (rounded).
- `tok`: mean tokens in the final poem.
- `s`: mean seconds per poem.
- `logp`: mean log-probability of the chosen tokens.
- `valid_mass`: the mean model probability on allowed tokens.
- `argmax_valid`: the share of steps where the model's own first choice was
  allowed.
- `bt`: mean backtracks.

`report.md` counts every token chosen from the model's distribution, including
tokens later undone by backtracking; forced line breaks and end-of-text are not
counted. Its "tokens" can therefore exceed `summary.md`'s `tok`.

## The runs

### 2026-09-24_e4b_baseline

**What:** free generation by **Gemma-4 E4B** (`google/gemma-4-E4B-it`, BF16),
the baseline for every constrained run.

**How:** the enforcer only watched. Launched as:

```bash
python -m metrical_decoder run --model google/gemma-4-E4B-it --modes baseline \
    --meters all --topics default --seeds 42,49,56,63,70 --out RUN_DIR
```

**Result:**

| poems | ended by | in meter | mean tokens | mean seconds | chosen-token logp |
|---|---|---|---|---|---|
| 555 | end of text 554, budget 1 | **0** by any verdict | 65 | 11.7 | −0.84 |

**Files:** `run.json`, `prompts.jsonl`, `results.jsonl`, `traces.jsonl`,
`summary.md`, `run.log`.

### 2026-09-24_control_regs

**What:** the first random-logit control after the prāsa and yati registers
were added (EXP-12). There is no model: logits are random over the Gemma-4 E4B
vocabulary slice (tokenizer only, CPU). A dead end or an engine rejection here
is an enforcer bug, since no model can be blamed.

**How:** `python -m metrical_decoder control --tokenizer google/gemma-4-E4B-it
--out GROUP_DIR --meters …`, with the 3 constrained strategies on T1, in
parallel groups:

| group | meters | seeds | poems |
|---|---|---|---|
| `g1`–`g4` | all 37 meters, in 4 groups | 42, 49 | 222 |
| `bahuyati_a` | మానిని, కవిరాజవిరాజితము | all 5 | 30 |
| `bahuyati_b` | మహాసృగ్ధర, మంగళమహశ్రీ, సృగ్ధర | all 5 | 40 (stopped at 40 of 45) |

`bahuyati_a` and `bahuyati_b` are reruns of the meters with three-akshara yati
groups, made after the fix below.

**Result:** 286 / 292 complete, and every complete poem is accepted by the
engines (no enforcer/engine disagreement). The 6 dead ends each led to a fix
(plan §12):
- **5 in `g4`** (మానిని ×3, కవిరాజవిరాజితము, మంగళమహశ్రీ): బహుయతి నియతి.
  The caesuras of a yati group must share one constituent of the vaḷi, and the
  registers had checked each target alone. After the fix, `bahuyati_a` is
  30 / 30 complete.
- **1 in `bahuyati_b`** (సృగ్ధర, masking-only, seed 70): a word ending in two
  dead consonants (వన్స్), which the prāsa engine splits differently from the
  scanner. The orthography filter now allows at most one dead consonant at a
  word's end.

### 2026-09-24_control_final

**What:** the random-logit control with all three constraints, run before the
first model grid.

**How:** 37 meters × 3 strategies × 5 seeds on T1 = 555 poems, in 5 parallel
groups (`g1`–`g5`).

**Result:** 554 / 555 complete, all accepted by the engines.
- **The one dead end** was సీసము (masking-only, seed 49). An all-laghu line
  fits two సీసము slots that place the yati differently, so the yati of neither
  was enforced.
- **Fix:** liveness is a disjunction over the slots still possible, given the
  lines already written.
- **Verification:** 15 / 15 సీసము poems then completed (plan §12). That rerun
  is not stored here; this folder keeps the original run.

### 2026-09-24_e4b_constrained

**What:** **Gemma-4 E4B** with the three constrained strategies, gaṇa + prāsa +
yati enforced (strict). It uses the baseline's prompts, topics, seeds and
decoding config: 37 × 3 × 5 × 3 = 1,665 poems.

**How:** `experiments/scripts/run_e4b_constrained.sh` (`metrical_decoder run
… --enforce gana,prasa,yati --profile strict --mask-workers 4`, with the memory
watchdog).

**Result:** every poem is complete and in meter, with no dead end.

| strategy | poems | in meter | mean tokens | mean seconds |
|---|---|---|---|---|
| masking-only | 555 | **555** | 110 | 20.4 |
| masking + backtracking | 555 | **555** | 102 | 33.2 |
| hybrid | 555 | **555** | 104 | 11.4 |

Token-level results (plan §14, before the vowel rerun below):

| | chosen-token logp | model's first choice overridden | words in the corpora |
|---|---|---|---|
| free baseline | −0.84 | — | 41% |
| masking-only | −2.18 | 31% | 17% |
| masking + backtracking | −2.29 | 35% | 20% |
| hybrid | −2.34 | 32% | 19% |

The constraint bites hardest at yati aksharas (50–54% overridden) and at prāsa
aksharas (42–47%).

**History:**
1. **Launched 2026-09-24** with a token budget of 2 × aksharas + 16
   (`run_2026-09-24_initial.json`).
   - 80 poems stopped at that budget, a median 94% of the way through: under
     the mask the model often writes one character per token.
   - The budget became the provable bound in `run.json`, and the 80 were rerun
     on 2026-09-25. Each reproduced its first trace exactly up to the old
     cut-off, then completed.
   - The replaced rows are in `superseded_budget_*.jsonl`. 4 of them had in
     fact been complete (a status off-by-one, since fixed).
   - `run_before_vowel_rerun.json` is the configuration of that relaunch.
2. **2026-09-26: the vowel rule**, "a word may not be dead consonants alone"
   (see [`2026-09-25_diffusion_constrained`](#2026-09-25_diffusion_constrained)).
   - `audit_rule_change.py` flagged 420 poems whose decisions the rule could
     have changed (`rule_audit.json`, with the reason for each).
   - They were moved to `superseded_vowel_*.jsonl` and regenerated with the
     same prompts, seeds and settings (`rerun_vowel_chain.sh`, finished
     2026-09-26 13:20).
   - The current `run.json` is that rerun's.

`report.md` / `report.json` (the baseline and this run) were written on
2026-09-25, **before** the vowel rerun: 420 of their poems have since been
regenerated. Rebuild them with `python -m metrical_decoder report
2026-09-24_e4b_baseline 2026-09-24_e4b_constrained`.

**Traces:** split in two (`TRACES_SPLIT.txt`).

### 2026-09-25_diffusion_trial

**What:** the first **DiffusionGemma 26B-A4B** trial: 37 meters × 3 strategies
on T1, seed 42 (111 poems). It uses the frozen-prefix canvas and the empty
thinking-channel prefill, and the end-of-text token is still allowed.

**How:** `metrical_decoder diffusion … --topics T1 --seeds 42` (the `diffusion`
CLI; plan §15).

**Result:** 111 / 111 complete and in meter, but **48–61% of words were single
aksharas**, by strategy (real verse 4.0%). The traces show why:
- Block diffusion plans where its reply ends. It drafted a short free-verse
  reply and filled the rest of the block with end-of-text.
- 52% of the tokens the constraint had to choose came where the model's first
  choice was end-of-text.
- Its mass on allowed tokens there had a median of 0.000.

This led to the fix tested in the next run.

### 2026-09-25_diffusion_trial_noeos

**What:** trial 2, the same as trial 1 with **end-of-text tokens removed from
the model's predictions everywhere in the canvas** (`forbid_end`, now the
default). The poem cannot end before the enforcer allows it; the traces keep
the raw predictions.

**Result:** 111 / 111 complete and in meter. Single-akshara words in the first
poems fell from 80% to 27% and from 57% to 21%. The words that replaced the
filler are still mostly not real words, so the model's vocabulary of fitting
words is now the limit.

These rows are the T1 / seed-42 cells of the full grid below.

### 2026-09-25_diffusion_constrained

**What:** the full **DiffusionGemma** grid: 37 × 3 × 5 × 3 = 1,665 poems, with
the same settings as trial 2 and the E4B runs' prompts.

**How:** `experiments/scripts/run_diffusion_constrained.sh RUN_DIR default
42,49,56,63,70` (`--resident`, 4 mask workers, watchdog, memory trace). The 111
T1 / seed-42 rows were copied from `2026-09-25_diffusion_trial_noeos`
(`SEEDED_FROM.txt`); the runner resumes by key.

**Result:** every poem is complete and in meter, with no dead end.

| strategy | poems | in meter | mean tokens | mean seconds |
|---|---|---|---|---|
| masking-only | 555 | **555** | 104 | 22.5 |
| masking + backtracking | 555 | **555** | 103 | 44.7 |
| hybrid | 555 | **555** | 100 | 23.2 |

**History:**
1. **The machine crashed hard** about 40 s into the first model load
   (2026-09-25 17:18; cause unproven). The relaunch at 18:52 added a memory
   trace synced to disk (`mem_trace.log`) and loaded cleanly.
2. **The first complete grid had 2 masking-only dead ends** (ఇంద్రవజ్ర and
   శాలిని, T2, seed 63).
   - In both, the model opened the last line with `న్` as a word of its own.
     The scanner reads it as an empty akshara, which became the line's vaḷi,
     and no akshara can meet an empty vaḷi in yati.
   - No corpus line has such a word (0 of 49,661).
   - **Fix:** the orthography filter forbids a word of dead consonants alone.
   - `audit_rule_change.py` then flagged 423 poems of this grid (and 420 of
     E4B's). They were moved to `superseded_vowel_*.jsonl` and regenerated
     (2026-09-26 09:07–12:12), gated on
     [`2026-09-26_control_vowel`](#2026-09-26_control_vowel).
   - `run_before_vowel_rerun.json` is `run.json` before the rerun.

`report.md` / `report.json` were written after the rerun and are current.

**Traces:** split in two (`TRACES_SPLIT.txt`).

From `meter_engine/` with the repo's `.venv`:

```bash
python -m metrical_decoder control --tokenizer google/gemma-4-E4B-it --out RUN_DIR      # random-logit control
python -m metrical_decoder run --model MODEL --out RUN_DIR --meters all \
    --modes baseline,masking_only,masking_backtrack,hybrid --topics default \
    --seeds 42,49,56,63,70 --enforce gana,prasa,yati --profile strict --mask-workers 4

python -m metrical_decoder summarize RUN_DIR                                          # summary.md
python -m metrical_decoder report RUN_DIR [RUN_DIR …]                                 # report.md
```
